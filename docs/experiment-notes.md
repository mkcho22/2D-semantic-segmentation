# 실험 결과와 근거

[실험 결과 CSV](../results/experiments.csv)는 **2025년 수정 발표 자료 10쪽에 기록된 12개 실험**을 옮긴 것이다. 수치는 당시의 validation 결과이며, 이 저장소를 정리하면서 새로 학습하거나 측정한 값이 아니다.

## 주요 결과

| 구분 | 설정 | 기록된 validation mIoU |
| --- | --- | ---: |
| 제출 설정 A4 | AdamW · CE + Dice · LR 0.0002 · batch 4 · weight decay 0.01 | 54.85% |
| 수정 발표 표의 최고값 A6 | AdamW · CE + Dice · LR 0.0002 · batch 2 · weight decay 0.01 | 55.14% |
| AdamW 비교 기준 A2 | AdamW · CE + Dice · LR 0.0001 · batch 4 · weight decay 0.01 | 53.15% |
| SGD 중 최고값 S4 | SGD · CE + Dice · LR 0.01 · batch 4 · weight decay 0.0001 | 53.42% |

A2에서 학습률만 0.0001 → 0.0002로 변경한 A4는 기록상 mIoU가 **1.70%p** 높다. A4보다 batch size를 줄인 A6는 mIoU가 **0.29%p** 높지만 validation loss는 0.4175 → 0.4647로 증가했다. 반복 실험의 평균이나 통계적 유의성을 뜻하지 않는다.

수정 발표에서는 A4가 강조되어 있으며, 제출 코드의 활성 설정과 체크포인트 이름도 A4에 대응한다. 따라서 **A4를 제출 설정, A6를 수정 발표 표의 최고 mIoU**로 구분한다. A4 선택 이유를 특정한 속도·메모리·일반화 이점으로 단정할 근거는 남아 있지 않다.

`validation_miou_percent`는 0~100 단위다. `reported_convergence_epoch`는 발표 표의 “수렴 Epoch”를 그대로 옮겼으며, best epoch나 실제 종료 epoch와 같다고 가정하지 않는다. 서로 다른 손실 함수의 loss 값은 직접적인 성능 순위로 비교하지 않는다.

## 자료 간 차이

| 자료 | 확인되는 내용 | 적용 방식 |
| --- | --- | --- |
| `2D Semantic Segmentation 수정본.pdf`, 10쪽 | A1~A6, S1~S6의 12개 결과. A4 54.85%, A6 55.14% | 이 저장소 실험 표의 기준 |
| `2D Semantic Segmentation.pdf`, 10쪽 | 이전 표에 A7 72.91% 기록. 일부 case의 손실 함수와 결과가 수정본과 다름 | 수정본과 혼합하지 않음 |
| `발표 대본.docx`, 결과 설명 | 손실 함수 비교 후 학습률, batch size, weight decay 순으로 조정한 과정과 A4 선택 서술 | 실험 과정의 보조 근거 |
| `자동차인공지능 프로젝트 성능기록 표.xlsx`, Sheet1 | A1~A8, S1~S8 실험 계획. 결과 열 K:P는 미기입 | 수행 완료·성능 수치의 근거로 사용하지 않음 |
| 제출 코드 `main.py`, `train.py` | AdamW, LR 0.0002, batch 4, weight decay 0.01, 활성 CE + Dice 조합 | A4 제출 설정 확인 |

이전 표의 72.91%와 수정본의 결과가 달라진 정확한 이유는 자료만으로 확정할 수 없다. 이전 표에서 수정본으로의 변화를 성능 향상·저하나 동일 조건 재실험으로 해석하지 않는다. 최종 제출본의 체크포인트는 `segmentation_model_A4_2.pth`이며, 모든 case의 실행 로그·체크포인트가 보존되어 있지는 않다.

원본 발표의 내보내기 시각은 2025-11-28, 수정본은 2025-12-02로 기록되어 있다. 이는 PDF 메타데이터의 생성일이며 개별 실험 일시를 뜻하지 않는다. 원본 과제·발표 자료에는 학내 정보가 포함되어 있어 이 저장소에는 필요한 사실만 정리했다.

## 데이터와 평가 범위

과제 안내 `Project_ver2 (1).pdf` 8~10쪽은 [Semantic Segmentation for Self Driving Cars 데이터셋](https://www.kaggle.com/datasets/kumaresanmanickavelu/lyft-udacity-challenge)을 출처로 제시한다. 과제 안내에 기재된 분할은 **training 1,000장, validation 1,000장, 별도 test set 없음**이며 입력 크기는 **800 × 600**이다. 과제 규정은 추가 데이터와 pretrained 모델 사용을 제한한다. 현재 보관된 스냅샷은 검증 라벨 한 장이 누락되어 999쌍이며, 자세한 현황은 [재현 안내](reproducibility.md#데이터-준비)를 참고한다.

라벨은 CARLA의 기존 **13개 클래스(ID 0~12)** 체계다. [CARLA 0.8.4 공식 문서](https://carla.readthedocs.io/en/0.8.4/cameras_and_sensors/#camera-semantic-segmentation)는 RGB 이미지의 red channel에 class ID를 저장하는 규칙과 클래스 목록을 설명한다. 이 문서는 라벨 해석의 근거이며, 데이터 생성에 사용된 정확한 CARLA 버전을 확인했다는 뜻은 아니다.

평가 해석에는 다음 한계가 있다.

- 실험 설정 선택에 validation 결과를 사용했으므로 독립 test 성능으로 해석할 수 없다.
- 표에는 단일 결과만 남아 있어 seed 간 분산과 재현 오차를 계산할 수 없다.
- 시뮬레이터 이미지의 결과이며 실제 도로 영상이나 차량 배포 성능을 입증하지 않는다.
- 수정 발표 11쪽의 정성 결과에서는 도로·식생의 큰 영역을 구분하지만 건물, 차량 및 경계 부근에 오분류가 보인다. 해당 이미지는 예시이며 클래스별 IoU를 대체하지 않는다.
